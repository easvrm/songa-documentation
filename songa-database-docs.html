Chapter 01

Overview & Architecture

What the Songa Mobility Platform database contains, how its 69 tables are organised into 9 domains, and the conventions that apply across the schema.

1.1 Overview

The Songa Mobility Platform (SMP) is a clean energy and agri-logistics ecosystem operating across Kenya. It connects electric trike drivers, battery charging infrastructure, agricultural supply chains, and farmer networks through a unified multi-tenant architecture.

This document is the working model reference for the SMP production database — extracted directly from the live PostgreSQL schema dump. It covers all 69 tables organised into 9 functional domains, with every table described at both the domain and column level.

Schema source: Source of truth for this document is the production schema dump dated May 2026 (smp_production_db). Column names, types, and counts reflect the actual database structure with no additions or interpretations.

1.2 Architecture at a Glance

The database follows a multi-tenant architecture where operational tables are scoped to a tenant via tenant_id. Each tenant is an independent operator organisation with its own drivers, trikes, hubs, batteries, and rate configurations.

1.3 Key Schema Conventions

ConventionMeaning
idEvery table uses an integer primary key (except tenants, which uses a varchar id).
tenant_idOperational tables carry tenant_id (varchar) as a logical foreign key scoping all data per operator.
is_activeSoft-delete pattern throughout. Records are deactivated, not physically removed.
submitted_at / created_atAudit timestamps on most tables for record creation.
submitted_by / updated_byUser attribution columns trace who created or last modified a record.
_v3 suffixThird-generation tables (drivers_v3, batteries_v3, trikes_v3, etc.) are the current active schema.
json / jsonb columnsSeveral tables use JSON for flexible payloads — stops, trike_change_reason, meta_data, area_coords.
No FK constraintsReferential integrity is enforced at the application layer. No FOREIGN KEY constraints exist in the database.
erp_timestampPayment tables include erp_timestamp (replaces earlier wcp_timestamp) for ERP system reconciliation.
